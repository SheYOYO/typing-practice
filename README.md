# 哪吒打字 · 文章打字练习（离线复刻）

> 一个**零依赖、零构建、纯离线**的文章打字练习应用。
> 双击 `index.html` 就能用 —— 不用装环境、不用联网、不用起服务器。

看字打汉字：屏幕上给出文章，你用手指在键盘上把它敲出来。
**拼音只做提示，判分只看你打出来的汉字对不对**（逐位比对，一个标点都不放过）。

仓库地址：<https://github.com/SheYOYO/typing-practice>

---

## ✨ 项目特色

### 1. 判分逻辑：拼音只是提示，汉字才是答案
屏幕上的拼音提示（`sheng`）永远**不参与判分**。
只有当你用输入法真正把「生」这个**汉字**上屏，才算打对一个字；打错立刻标红，逐位比对。

### 2. 中文输入法友好：组字期间绝不误判
用拼音输入法打「生活」时，会先出现 `shenghuo` 这串字母。
**这串字母在输入法组字期间不参与任何判定**，不上屏就不算——彻底避免了「拼音还没变汉字就被判全错」的经典 bug。
（另外：纯英文、空格结尾的输入在中文文章里一律不计入成绩。）

### 3. 像素级「逐格对齐」
打出来的字与上方目标字**严格同列**，第 20 个字也不会累积跑偏。
做法是先用真实排版测出每个字符在当前字号下的推进宽度，再把每格宽宽钉死
（实测最大偏移 **0.00px**，汉字与全角标点都成立）。

### 4. 自带文章导入：一段话就能开练
首页「导入我自己的文章」是一排**组块按钮**，四个入口一目了然：

| 按钮 | 作用 |
|---|---|
| **＋ 自定义文章** | 打开编辑框，自己写或粘贴一篇 |
| **📄 导入文档** | 从 **.txt / .md / .docx** 读取，自动抓标题与作者 |
| **🗑 删除** | 进入删除模式，再点卡片即删（可撤销） |
| **⚡ 示例** | 打开编辑框并填入一段示例文本 |

- 「自定义文章 / 导入文档 / 示例」都打开**同一个编辑框**，点「确认导入」才真正入库
- 编码自动识别（UTF-8 失败自动回退 GB18030，中文老文件不乱码）
- `.docx` 用**浏览器原生 `DecompressionStream`** 解压取 `word/document.xml`，不引第三方库
- 单篇上限 5 万字，超过 1 万字会提醒
- **入库后**卡片右上角的 **✎** 可以随时再编辑；改完 **id 不变，练习进度与最好成绩都保留**

### 5. 文章标点自动统一为中文标点
导入或内置的文章，里面的半角标点会被自动换成中文标点：
`, . ! ? ; : ( ) [ ] < > ~ " '` → `，。！？；：（）【】《》～“”‘’`，
`...` → `……`、`--` → `——`。
数字里的小数点与千分位（`3.14`、`1,000`）、单个连字符（`a-b`）、以及代码味符号不会被误伤；
转换是**幂等**的，所以历史文章打开时也会被自动修正。

### 6. 换行与每行字数按原站实测校准
不是「凭感觉像」，而是抓原站真实页面逐项量出来的：
标题文案、统计条（`0CPM` 起步）、底栏 `上一关 / 下一关`、快捷键条、
**字号档位 16/20/30/40/50/60/70/80/90px（默认档 3 = 30px）**、行卡片 900px、
**每行 27 字**。

> 关键点：原站那个「一行装得下几个字」的测量探针**恒为 30px**（它的 `.input_box`
> 是写死 30px 的，字号档位只改上方目标字），所以原文的**每行字数恒为 27，与字号无关**。
> 本项目照搬这一结论 —— 你在设置里把「中文大小」调到 16px 或 90px，
> 每行依然是 27 字、分行位置与原站逐行一致。

### 7. 其他
- 🎨 **11 套背景主题** + 深色模式，选择自动保存
- 🔊 音效用 **zzfx 实时合成**（打对 / 打错 / 结算星星），不带任何音频文件
- 📊 结算页：五星评级 + 准确率 / 速度 / 时长三条进度条 + 段位称号
- 💾 进度与设置只存 `localStorage`，**不联网、不上传任何数据**
- 🧹 删除文章走「两步确认 + 可撤销」，内置文章受保护

> 说明：朗读键按需求从原站的「空格」改成了 **右 Ctrl**（空格因此恢复成普通输入键）。

## 🧱 技术实现

**零第三方库、零构建工具、原生 ES5 + DOM。** 整个项目就是 `index.html` + `css/` + `js/`，没有 `npm install`。

| 难点 | 做法 |
|---|---|
| 逐格对齐 | `measureWidths()` / `applyCharWidths()`：按字号缓存真实推进宽度并写入每格 |
| 折行 | `getMaxCharsByFilling()`：二分测出输入框装得下几个字（照搬原站算法，`-2`、最小 10） |
| 输入法组字 | `compositionstart/end` 期间不判定 |
| `.docx` 解析 | 原生 `DecompressionStream('deflate-raw')` 解 zip |
| 中文编码 | `TextDecoder` 以 `fatal` 试 UTF-8，失败回退 `gb18030` |
| 音效 | zzfx 合成器，运行期生成波形，无音频文件 |
| 数据持久化 | `localStorage`（文章 / 进度 / 设置三份键） |

## 🔧 维护与发布

仓库已按模块分好提交历史（`util → pinyin → audio → articles → engine → result → app → 样式 → 素材 → 入口 → 文档`），
改完之后照常走 git 即可：

```bash
git add -A
git commit -m "fix: 修掉 XXX"
python .planning/tools/push_to_github.py     # 推送 + 自动核验本地/远端 SHA 是否一致
```

> ⚠ 本机把 `github.com` 解析到一个**不可达的 IP**，直接 `git push` 会超时、走系统代理也是 502。
> `push_to_github.py` 会自动起一个 **仅监听 127.0.0.1 的临时中转**，把 `github.com:443`
> 转发到实测可达的 GitHub 边缘 IP，推完即关（不改 hosts、不动系统配置）。
> 令牌从 **Windows 凭据管理器**读取，**不落盘、不打印明文**。

```bash
python .planning/tools/push_to_github.py --check   # 只核验，不推送
```

## 🧪 回归测试

改完代码建议跑一遍（需要 `playwright-core` 与 Chromium）：

```bash
# 1) 起本地静态服务
python -m http.server 8899 --bind 127.0.0.1

# 2) 全量回归：逐格对齐 / 组字不判定 / 打对打错着色 / 字号档位 / 主题 / 窄窗 / 控制台零报错
node .planning/tools/regression.cjs

# 3) 端到端：打完一篇 → 落到结算页
node .planning/tools/e2e_finish.cjs

# 4) 规划文件分层校验
python .planning/roadmap_check.py
```

`tools/` 里还有 `measure_origin.cjs` / `compare_widths.cjs` 等**同口径实测脚本**，
用来把「本项目」和「线上原站」放在同一组视口宽度下逐项对比。

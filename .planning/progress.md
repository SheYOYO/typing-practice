## 2026-10-11 11:10 — 第四轮：逐格对齐 + 万字上限 + 交互组件视觉还原

需求（三条）：① 打出的每个汉字与标点都要和上方目标字逐格对齐；② 导入字数上限 ≥ 一万字；
③ 交互组件（线条/宽度/颜色深浅）的视觉效果尽量还原原站。

### 定位到的根因（视觉不还原）
第一版 CSS 偏离原站较多，逐项比对 `v.mamioo.com/static/dazi/level.css`（53KB 原版，已下载核对）：
- `.word_label` 多了 `padding:0 1px`、`.input_box` 多了 `padding:0 4px` → **每格 +2px + 整行右移 4px**
- `.word_cursor` 用灰 `#8D8D8D` 且默认不可见；原站是当前行 **`#205b02 @ .3`** 通铺下划线
- 卡片没有 `min-width:900px / max-width:1200px` 的宽度模型，也没有 `inset 0 0 4px rgba(84,53,7,.2)`
- 工具面板 top/宽度/阴影、分隔线 `#CCC`、li 间距 20px、h1 padding 20px/max-width 500px、
  背景缩略图 150px、按钮 16px + hover 上浮 —— 全部与原站不一致
- 深色下原站是 `#000 / header #666 / 卡片 #666 / 字 #eee / 输入 #333`（靠 `.level_line` 类生效）

### 逐格对齐的实现（关键）
输入框与 `.word_label` 同字体同字号同字距时，同字符推进宽度理论一致；但字体回退/全角半角标点/
空格会造成偏差，且**沿行累积**导致后半行越走越歪。因此：
- `measureWidths()`：用真实 DOM 排版批量量出每个字符在当前字号下的推进宽度，按字号缓存
- `applyCharWidths()`：把宽度写死到 `.word_box` 上（字号切换 / 首次渲染时调用）
- `.words_box { white-space: nowrap }` + 两边 padding 归零 + `padding-left:1px` 抵消 input 左边框
- 实测：39 字行 + 7 个标点，**最大偏差 0.00px**；字号 8 档同样 0.00px

### 其他改动
- `js/app.js`：`MAX_CHARS=50000` / `WARN_CHARS=10000`，一万字内不再弹确认；导入框实时字数（app.css 三态配色）
- `js/engine.js`：渲染改「拼 HTML 一次性落地」（万字提速）；打超字符带入下一行；行首不打错音；
  窗口 resize 仅在未开始且每行字数变化时重新折行
- `index.html`：加 `data:,` favicon 消掉 404

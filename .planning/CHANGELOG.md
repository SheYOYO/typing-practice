## v0.10 — 打对的字改黑 + 移除「清空练习进度」（2026-10-11）

**他一句话**：打对的字的颜色要求是黑色的（参照原网站的颜色）；清除练习进度的功能删除，
注意不要影响其他功能。

**改了什么**：
1. 打对的字 **#0086d2 蓝 → #333333 黑**（与正文汉字同色）；打错的字仍 `#ff5e7c` 粉红。
   深色主题下加了一条覆盖，保证打对 = `#eee`，不会在深底上糊掉。
2. 主页删除「清空练习进度」按钮及其监听，连带清掉只被它用的 `.btn-mini`。

★ **最要紧的判断（也是必须说清的一处）**：
**原站打对的字其实是蓝的**，不是黑的。四条独立证据（两处 level.css 原文、原站真实页面级联实测、
走原站自身 `processPara` 判定逻辑实测）都是 `rgb(0,134,210)`。
本次按用户明确要求改为黑；**要回退成原站蓝，只需把 `css/level.css` 里
`.level_para_line .correct .word_label` 的 `#333333` 换回 `#0086d2`（注释里已写明）。**

**未动（安全边界）**：`setProgress()` 本体、卡片「最好 N WPM」、进度存储结构、
导入/删除/撤销、判定逻辑、逐格对齐、折行 —— 全部实测不受影响。

**验收**：`regression.cjs` **31/31**（新增 3 项：清空按钮不存在 / 导入删除按钮仍在 /
打对=rgb(51,51,51) / 打错=rgb(255,94,124) / 深色打对=rgb(238,238,238)）；
`e2e_finish.cjs` 8/8；`file://` 直开 0 报错。

## v0.9 — 打字页「文案 / 字号 / 每行字数」按原站实测校准（2026-10-11）

**他一句话**：打字练习交互页面的文案和原网站不一样，字体的大小不一样，一行的文字数也不一样，参照原网站修改。

**取证**：抓原站真实页面（`level_29-2-101.html` + `level.css` + `main.css` + `student.js`）
存 `reference/origin/`，再用 playwright-core 在 7 个视口宽度下**同口径实测两边**。

**改了什么**（对外可见）：
1. 标题 → `哪吒打字 打字练习文 散文一百篇[《豁达》]`（原站原格式，`[篇名]` 方括号）。
2. 统计条 → 时间初始 `00:00:00`、**速度初始 `0CPM`**（开始后才是 `{n}WPM`）；空格排版照原站。
3. **时间运行中改「分:秒」**（`00:03`），不再是 `00:00:03` —— 原站 student.js 的小时段被注释掉了。
4. 底栏 → **`上一关` / `下一关`**（`下一关` 蓝底 `.active`），真正可点（跳相邻文章）；
   旧的 `上一个 / 跳过本行` 此前没绑事件，一并修掉。
5. 快捷键条 → 只留原站三条：`空格 朗读` `←→ 翻页` `Ctrl + Alt 提示`（去掉自加的 `Esc 返回`）。
6. **字号档位换成原站刻度**：16/20/30/40/50/60/70/80/90px，默认档 **3**（原为 18~52px、档 5）；
   类名改 `.font_label_sizeN`；面板文案改「中文大小：」并显示当前档位。
7. `.level_para_line` 换成原站四段响应式 max-width，**删掉自加的窄屏重排断点**。
8. 顶栏工具字号 14px → **12px**（原站值）。
9. 旧存档字号档位按实际像素就近迁移，避免字突然变大。

★ **最要紧的判断**：**「一行的文字数」与「字号」是同一个问题。**
两边行宽都被 `min-width:900px` 锁死为 900px（7 个宽度实测全一致，27 字），
所以每行字数只由字号档位决定 —— 档位刻度一换成原站原值，两个问题同时消失。

**验收**：`.planning/tools/regression.cjs` **26/26 全绿**（逐格对齐 0px、组字期不判定、
打对 8 字 = 8 个 `.correct`、档位 1/3/9 = 16/30/90px、深色、背景、800px 窄窗不裁切、
控制台 0 报错）；`e2e_finish.cjs` 通关 8/8；`file://` 直开：主页 10 卡 + 打字页 30px/27 字/0 报错。

**未动（等用户发话）**：快捷键条原站默认 `opacity:0` 隐藏（我方常显）、启动遮罩
「鼠标点我 或 按 空格键 开始」原站有、结算页速度/时长单位（见 `F19.5`）。

## v0.8 — 删除入口改「按钮式两步删除」（2026-10-11）

**他一句话**：删除文章的组块放在导入文档和填入示范文档的中间，视觉效果同两者，点击后激活删除再点击文章即删除。

**改了什么**（对外可见）：

## v0.5 — 换行/分行 100% 照搬原站（2026-10-11）

**他一句话**：练习文案换行的标准跟原网站一样（句号换一行、字数达到就换下一行）。

**改了什么**：`pinyin.js splitSentences()` 按 `\n` 分行 + 句末标点补切；`engine.js getMaxCharsByFilling()` 照搬二分定长续切（-2、最小 10）。

★ **最要紧的判断**：**原站不是按句号分句**，是「服务端按 `\n` 分行 → 前端二分定长续切」。之前误加 30 字硬切，已去掉。

**验收**：4/4 篇（101/102/103/104）逐行完全一致，含 27+2 腰斩那句。

## v0.4 — 逐格对齐 + 万字上限 + 交互视觉还原（2026-10-11）

**他一句话**：打出每个汉字和标点都要和上方目标字逐格对齐；上传字数确保一万以上；交互组件线条/宽度/颜色深浅尽量还原。

**改了什么**：对齐靠「padding 归零 + nowrap + `applyCharWidths()` 钉宽」；`MAX_CHARS=50000`；`css/level.css` 按原站取值整篇重写。

★ **最要紧的判断**：对齐是「同字体 + 全员 padding:0」的自然结果，任何一边加水平 padding 都破坏；宽度漂移会沿行累积。

**验收**：39 字行含 7 标点偏差 0.00px；字号 8 档同样 0.00px。

## v0.10 — 打对的字改黑 + 移除「清空练习进度」（2026-10-11）

**他一句话**：打对的字的颜色要求是黑色的（参照原网站的颜色）；清除练习进度的功能删除，
注意不要影响其他功能。

**改了什么**：
1. 打对的字 **#0086d2 蓝 → #333333 黑**（与正文汉字同色）；打错的字仍 `#ff5e7c` 粉红。
   深色主题下加了一条覆盖，保证打对 = `#eee`，不会在深底上糊掉。
2. 主页删除「清空练习进度」按钮及其监听，连带清掉只被它用的 `.btn-mini`。

★ **最要紧的判断（也是必须说清的一处）**：
**原站打对的字其实是蓝的**，不是黑的。四条独立证据（两处 level.css 原文、原站真实页面级联实测、
走原站自身 `processPara` 判定逻辑实测）都是 `rgb(0,134,210)`。
本次按用户明确要求改为黑；**要回退成原站蓝，只需把 `css/level.css` 里
`.level_para_line .correct .word_label` 的 `#333333` 换回 `#0086d2`（注释里已写明）。**

**未动（安全边界）**：`setProgress()` 本体、卡片「最好 N WPM」、进度存储结构、
导入/删除/撤销、判定逻辑、逐格对齐、折行 —— 全部实测不受影响。

**验收**：`regression.cjs` **31/31**（新增 3 项：清空按钮不存在 / 导入删除按钮仍在 /
打对=rgb(51,51,51) / 打错=rgb(255,94,124) / 深色打对=rgb(238,238,238)）；

## v0.12 — 朗读键 / 中文标点 / 每行字数（2026-10-11）

**他一句话**：① 取消空格激活自动朗读，改成右 Ctrl ② 文章里的标点统一为中文标点
③ 换行逻辑跟原站不对（一行字数太多、有标点独占一行），要求照搬原站。

**改了什么**：
1. **朗读键 空格 → 右 Ctrl**（`engine.js` `bindKeys` 拆成 keydown/keyup 两个监听）。
   `Ctrl + Alt 提示` 与右 Ctrl 共用 Ctrl，故采用「右 Ctrl 按住期间被别的键打断就不朗读」
   的状态机，实测：右 Ctrl 抬起 = 朗读 1 次；空格 = 0 次；Ctrl+Alt = 0 次。
   快捷键条文案同步改成「右Ctrl 朗读」（这条**偏离原站**，是用户要求）。
2. **`Util.toChinesePunct()`**：半角 → 中文标点，幂等；在 `engine.mount` 渲染前统一过一遍
   （覆盖内置/导入/历史数据），导入时也过滤一次。数字小数点/千分位、单连字符、代码符号不动。
3. **每行字数修回原站的 27（与字号解耦）** —— 见下。

★ **最要紧的发现（第 12 轮，root cause）**：
原站 `.level_para_line .input_box{font-size:30px}` 是**写死的**，`.font_label_sizeN` 只改
`.word_label`。于是原站 `getMaxCharsByFilling()` 的探针**永远是 30px**，
实测原站 **档1(16px)/档3(30px)/档5(50px)/档9(90px) 的 per 全是 27**。
而本项目把 `.input_box` 的字号绑到了 `--hz-size`（为了逐格对齐），
导致 per 跟着字号走：**档1 → 53 字/行**、档5 → 15、档9 → 10
——「一行字数太多」+「标点被甩到下一行独占一行」由此而来。
**修法**：`getMaxCharsByFilling()` 里的探针字号钉死 30px（`PER_PROBE_FONT`），
真实 `.input_box` 仍跟随档位 → **per 恒 27 且逐格对齐仍然 0px**（实测档1/档5 都是 0px）。

**验收**：`regression.cjs` **41 项全绿**（新增 7b 每行字数×4 档、7c 朗读键×3、7d 标点×3）；
`e2e_finish.cjs` 8/8；`file://` 直开 per=27 / 30px / 0 报错；
`compare_breaks.cjs` 逐行对比**完全一致**。
